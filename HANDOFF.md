**Review findings (non-blocking, from the pre-merge review):**
- No `engines` field, while Prisma 7.10.1 needs Node ^20.19 / ^22.12 / ≥24. `@types/node` is `^20`.
- `postinstall` runs the `prisma` CLI, which is a devDependency, so any install that omits dev dependencies would fail.
- In `prisma/seed.ts`, an error thrown by `$disconnect()` would be unhandled and print raw.
- Example values in the `prisma/schema.prisma` comments differ from the seeded values (cosmetic).
- Fixed in revision 15: the stale header in the plan.

**Known gotchas:**
- Don't run `npm ci` or delete `node_modules` while `npm run dev` is running. On Windows the dev server locks native files, and an aborted `npm ci` leaves `node_modules` half-deleted (it happened once; see history entry 12).
- npm 11 skipped install scripts for `prisma`, `@prisma/engines`, and `unrs-resolver`. They were **not approved**, and generate, validate, and migrate deploy all worked without them.
- `lib/db.ts` imports `server-only`, so scripts can't import it; they build their own client, as `prisma/seed.ts` does.
- With Cache Components, any request-time database read must call `await connection()` inside a `<Suspense>` boundary.
